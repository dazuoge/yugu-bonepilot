# ARP BIP 扩展 · v3.2

给「驭骨 · BonePilot」v5.2.45 增加一个 **ARP 骨架专用的 BIP 式拖手**：
拖动 FK 手控骨时，上臂 / 前臂像 3ds Max Biped 那样 IK 跟随，但**结果写回 FK 旋转**，
不新增 IK 约束、不留下 IK 状态，`ik_fk_switch` 始终保持 FK（1.0）。

分支根目录的 `controller_navigator.py` 已经是整合好的单文件，**可直接 Install from Disk**。
本目录保留扩展源码，用于驭骨升级后被覆盖时重新植入。

## v2.9 修复：撤回后控制器不再残留隐藏（2026-11-16）

用户反馈：「BIP 移动完之后按一下撤回就又变成只有手掌控制器」。
BIP 是带 `UNDO` 的 operator，Blender 的撤销快照包含 `PoseBone.hide`，
Ctrl+Z 会把拖动中的独显态整个恢复出来；v2.8 的守卫只在独显快照尚未
`forget` 时有效，收尾之后按撤回就没人管了。

顺带查出 v2.8 的自愈判据在真实工程里**静默失效**：它要求「干净基准里
隐藏骨不到一半」，而 `E 踏步回斩.blend` 426 根里本来就有 350 根变形骨
`hide=True`，条件恒成立为假。v2.9 统一改成三个强特征——当前可见集恰等于
上次 keep、干净基准里可见却被藏起来的骨 >= 一半且 >= 3 根、干净基准里
隐藏却亮出来的骨（keep 除外）为 0；不再看隐藏骨比例。

| 防线 | 作用 |
| --- | --- |
| `undo_post` / `redo_post` | 撤回 / 重做后即时按干净基准还原显隐，姿态与关键帧零改动 |
| `@persistent` 装饰 | Blender 载入 .blend 会清空非 persistent 回调，装饰后跨文件存活 |
| 常驻定时器补装 | 每 0.5 s 按回调列表实况补装；不再用模块标志短路（实测标志会留在 True 导致永不重装） |
| 定时守卫 | 极端情况下快照已失效也能按干净基准兜底 |

回归：`verify_v29_undo.py` **30/30**（保留真实工程 350/426 隐藏分布）、
`verify_v28_solo.py` **38/38**、`verify_v27_solo.py` **36/36**；
全套 46 场景 37 PASS，其余 6 项与 v2.8 全套逐项一致，属工程被另存导致
硬编码基线失效，非代码回归。后台模式 `ed.undo` 被 Blender 禁用，专项回归
把显隐设成「撤销后恢复出的独显态」再走真实 handlers 列表触发同一代码路径。

## v3.0 修复：原生旋转模式下控件不再闪烁（2026-11-16）

用户反馈：「使用手掌控制器进行旋转模式旋转时，控件会闪烁」。

**根因**：驭骨原生 MOVE / ROT 模态与 BIP 用完全相同的规则独显控制器
（可见集 = 选中骨），`PoseBone.hide` 的数值分布**和 BIP 被撤销恢复出来的
残留一模一样**。真实工程 426 骨里干净态 74 根可见，两者都只显示 1 根，
`bip_solo_leak_signature()` 必然判成残留（实测 73）。于是 v2.9 的 0.5 s
定时守卫与 `undo_post` 守卫在旋转过程中把 73 根控制器整副亮回来，表现
就是「先全部隐藏，轻微一动又突然全部显示」。

数值上无法区分，只能靠**上下文：显隐现在归谁管**。

| 防线 | 作用 |
| --- | --- |
| `_bip_foreign_modal_active()` | 优先采信驭骨自己的 `_MODAL_ONCE` 闸门（真实 GUI 下只有它的 MOVE / ROT 会置位）；`window.modal_operators` 只认白名单，避免用户常驻插件把守卫永久关掉 |
| 定时 / 撤销守卫放行 | 外来模态在跑时一律不动显隐，并消费本轮兜底授权 |
| `_bip_solo_disarm()` | BIP operator 正常确认 / 取消 / 交还后立刻消费授权，只有 Blender 连 `cancel` 都没给的异常结束才留给定时守卫 —— 即使模态探测失效也不再补刀 |
| 撤销修复不变 | `undo_post` / `redo_post` 即时路径不依赖授权标志，v2.9 的「拖完按 Ctrl+Z」修复完整保留 |

无头回归用 `_BIP_FOREIGN_MODAL_PROBE` 注入等效上下文（后台起不了真 GUI
模态）；生产代码走闸门 + 模态算子白名单。

**A/B 复刻**（`diagnostics/diagnose_rot_flicker.py`，同一真实工程）：
无模态上下文时守卫 `changed 73 / FLICKER True`；带模态上下文后定时守卫与
撤销守卫均 `changed 0 / FLICKER False`；消费授权后定时守卫同样 `changed 0`。

回归：`verify_v30_flicker.py` **39/39**、`verify_v29_undo.py` 30/30、
`verify_v28_solo.py` 38/38、`verify_v27_solo.py` 36/36；全套 47 场景
38 PASS，FAIL 项与 v2.9 基线逐项一致（工程在 13:22 又被另存，画弧场景
多一项 `D1 原关键帧姿态不变 20.09°` 属硬编码基线随工程内容漂移）。

## v3.1 修复：ARP 原生 IK/FK 切换不再毁掉 FK 动画（2026-11-16）

用户反馈：「对一个已经做过 BIP 移动手掌控制器操作的 FK 手臂链，进行
AutoRig Pro 原生的 IK/FK 切换后又切回 FK，原本流畅的动画会直接崩溃、暴跳、乱转。」

**根因**（读 ARP 源码 `rig_functions.py` 并用 `D踏步上挑.blend` 复刻）：
`pose.arp_switch_snap` → `fk_to_ik_arm()` → `snap_rot()` → `set_pose_rotation()`
把 IK 链姿态用 `mat.to_quaternion()` / `q.to_euler(mode)` 直接写进 FK 控制器，
既不保证与相邻关键帧同分支，也不保证姿态与切换前一致；autokey 下还会插成
关键帧。实测一次 FK→IK→FK 往返把 f24 的 FK 关键帧姿态改写 **85.16°**，
逐帧 >12° 跳变 46 → 74，最大 54.7° → 85.9°。这不是「等价表示落错分支」，
现有 `bip_normalize_rotation_curves()` 对该曲线 `fixed=0`（姿态本身被换掉）。

| 防线 | 作用 |
| --- | --- |
| `_bip_ikfk_find_class()` | ARP 是 extension 动态注册，类名不一定挂在 `bpy.types`，按 `bl_idname` 扫 Operator 子类定位；常驻 timer 每轮补装，避免插件加载顺序影响 |
| `_bip_arp_switch_wrapped()` | 运行时包装 `execute`，不改 ARP 源码、不写 `.blend` 数据，`unregister` 原样还原 |
| FK→IK | 快照该侧 FK 链的旋转曲线（含关键帧值、手柄坐标与类型、插值），并记录 ARP 自己吸附后的 IK 控制器指纹 |
| IK→FK | 帧号与指纹都没变（用户没在 IK 下动过控制器）→ 逐帧原样恢复 FK 曲线；动过 → 尊重 ARP 匹配结果，只跑一次分支连续化 |
| 恢复精度 | 比较精度 1e-7、还原 `handle_*_type` 后再写手柄坐标，否则 Bezier AUTO 手柄会被重算、1e-6 量级脏值会残留 |

恢复成功后**不再跑连续化**，避免把用户原本干净的曲线也改掉（实测这一步
曾造成 15.56° 的中间帧漂移）。

**A/B 复刻**（`tests/_repro_ikfk.py`，同一真实工程）：
无保护往返 46 → 74 跳变 / 最大 85.9° / 关键帧姿态改写 85.16°；
v3.1 保护下真实工程 21 条 FK 曲线逐帧完全一致、姿态差 0.0396°（求值噪声）。
平滑动画对照：基线 0 跳变 → 无保护 4 跳变 / 12.56° → 有保护 0 / 0°。

回归：`verify_v31_ikfk.py` **18/18**（含 IK 下主动摆姿势仍尊重 ARP、
原 ARP 算子与 BIP 拖动算子完好）。

## v3.2 修复：IK/FK 快速切换改走 ARP 原生（2026-11-16）

用户复测指出：用**插件自带的 IK/FK 快速切换**（快捷键 I / O 面板）切完再切回
就暴跳，用 **ARP 原生切换**则没问题 —— v3.1 只保护了原生按钮这一条路。

**根因**：主文件的 `pose.cn_ikfk_toggle_v45` 走 `limb_switch()` →
`_switch_once(kind='calc')`。ARP 骨架由 `_limbs_animate()` 造出的 `CN_Limb`
不带 `rigify_to_fk/rigify_to_ik`，`has_native=False`，切换顺序被写死成
`['calc']`，**从不调用 `pose.arp_switch_snap`**。自算里：

1. `_snap_by_matrix()` 用 `pb.matrix = ...` 把 BIP 连续化后的 ±2π 分支压回主分支；
2. `_key_limb()` 紧接着把两侧控制器 location / rotation / scale 全量插帧，
   把这个主分支值钉成关键帧，夹在两侧 ±2π 帧之间 → 插值绕远路 → 暴跳。

实测（`D踏步上挑.blend`，f24，FK→IK→FK，2π 分支基线）：
自写切换 **54 跳变 / 最大 138.28°**；v3.1 保护下的 ARP 原生按钮 0 / 0°。
隔离实验证明自算 snap 本身不写曲线，单独换原生、或单独去掉全量插帧都够。

| 防线 | 作用 |
| --- | --- |
| `_bip_arp_limb_switch()` | 运行时替换模块全局 `limb_switch`，ARP 类骨架整条委托给 `pose.arp_switch_snap`；非 ARP 骨架（Rigify / 自带 snap）原样回退 |
| `_bip_arp_select_limb()` | ARP 按选中骨判 side/type，只选目标肢体一根 FK 控制器；临时放出被显隐同步藏起来的骨，避免 ARP 静默不生效 |
| `_bip_arp_key_limb()` | 原生路径下跳过驭骨的额外全量插帧（ARP 自己会插）；非 ARP 骨架照常插帧 |
| v3.1 指纹修正 | `c_arms_pole` 被 ARP 每次切换无条件重算，不能当「用户动过 IK」的证据，从指纹骨列表剔除；否则多条肢体连切会误判、放弃曲线恢复 |

不改主文件源码、不改 ARP 源码，禁用插件时 `limb_switch` / `_key_limb`
原样还原；`bip_register()` 与常驻 timer 都会幂等补装，规避加载顺序。

**实测**：`verify_v32_native.py` **32/32**（2π 基线 0 跳变、工程原样曲线
61→61 不加剧、全部肢体往返 0 跳变、非 ARP 回退、卸载还原、显隐/选择迁移
等原有行为保留）；`verify_v31_ikfk.py` 18/18、`verify_v30_flicker.py` 39/39。

## 整合结构

整合版 = 官方 v5.2.45 **逐字节原文件** + 3 处挂钩（`INVOKE` / `REGISTER` /
`UNREGISTER`）+ 1 个扩展块。扩展块之外的 13618 行与官方 md5
`7db954229ff5a0387e3a4fc2c2d23d95` 对应版本完全一致，没有改动任何原有功能。

驭骨升级后重新植入：

```bash
python install_bip_patch.py --file <新的 controller_navigator.py 路径>
python install_bip_patch.py --file <路径> --uninstall   # 还原成官方原版
```

## 使用

1. Blender 5.3 → Pose Mode，选中 ARP 的 FK 手控骨（如 `c_hand_fk.r`；命名不固定也能识别）。
2. 按 `Z`（驭骨的移动键）→ 命中手部控制器时自动切到 BIP 拖手。
3. 移动鼠标＝IK 跟随；松手提交，写回 `c_arm_fk` / `c_forearm_fk` 的 FK 旋转。
4. `Esc` 取消；`Alt + 滚轮` 切到别的骨会提交并交还驭骨原有模态。

依赖原有偏好：**独显控制器**（`solo_display`）、**确认后刷新运动路径**、Auto Key。
要先在 Object Data → Motion Paths 里 Calculate 出路径，才会看到轨迹实时更新。


## v2.8 修复：拖动结束控制器必定还原（2026-11-15）

真实工程复刻出 4 条残留路径，全部封死：

1. **交还驭骨失败**：v2.7 在该分支重新独显，可 BIP 紧接着返回 `FINISHED`，
   模态已经结束，那份 `hide=True` 从此无人还原（425/426 根骨）。现改为按快照还原。
2. **外部取消模态**：切模式 / 换文件 / 别的算子抢占时 Blender 调用 `cancel()`
   而不是 `modal()` 的 ESC 分支。v2.7 没有 `cancel()`，现在补齐，与 `_finish`
   共用还原逻辑，`_bip_ended` 保证不会二次 `bip_end` 回滚已提交姿态。
3. **脏快照被固化**：残留状态下再开一次拖动会把满屏 `hide=True` 抓成「开拖前
   状态」，之后怎么 restore 都回不来。现在开拖前按最近一次干净显隐自愈，
   判据极严（同骨架、>=90% 隐藏、基准里隐藏不到一半、可见集恰等于上次 keep），
   不会误伤用户手动隐藏的骨骼。
4. **零快照遗留**：新增模块级活跃标记 + 0.5 s 定时守卫；只要 BIP 模态已结束
   却仍有未还原的独显快照，就自动按快照还原。

| 复刻路径 | v2.7 | v2.8 |
| --- | --- | --- |
| 正常确认 | diff 0 | diff 0 |
| 交还失败 | 425/426 根残留 | diff 0 |
| 外部取消 | 425/426 根残留 | diff 0 |
| 残留后重开拖 | 399 根被抓成脏快照 | 自愈，快照干净 |

回归：`verify_v28_solo.py` **38/38**、`verify_v27_solo.py` **36/36**、
全套 45 场景中 39 PASS，其余 6 项经 A/B 对照（临时换回 v2.7 跑同一工程）
同样 FAIL，属工程被另存导致硬编码基线失效，非代码回归。

## v2.6 / v2.7 要点

- **v2.6**：修复「没切旋转顺序、画弧时照样暴跳」。真因是历史脏关键帧（四元数整组
  翻符号 / 欧拉落错分支），且 ARP 锁轴导致该帧只有部分通道有关键点，旧修复工具取
  「各通道交集帧」恰好漏掉它。改为并集帧 + 姿态等价校验；并在 BIP 起点、收尾插帧、
  驭骨自由旋转 / 移动插帧后自动对本次 FK 骨做局部归一化（只换数值表示，关键帧姿态
  逐帧零改变）。
- **v2.7**：BIP 也享受「只显示当前控制器」。原先这个功能长在驭骨自己模态的
  `_solo_apply` 里，而 BIP 在 `invoke` 阶段就分流接管，压根没进过那个模态。现在
  复用同一套机制：只写 `PoseBone.hide`，开拖抓一次显隐快照，确认 / 取消 / 异常 /
  交还 / 卸载逐骨还原。交还前必须先还原，否则驭骨会把 `hide=True` 当成原始状态。

## 边界

- 只针对 ARP 骨架；Rigify / AniMate 走驭骨原有逻辑，不受影响。
- FK 曲线插值不等同 IK 实时轨迹；5.3 的「转换旋转顺序」本身可能改变插值形态。
- 旧工程里残留的坏关键帧，第一次拖动或点一次 N 面板「修手臂」即会理顺。
- 覆盖安装后必须 **重启 Blender 或禁用→重新启用驭骨**，否则跑的还是内存里的旧代码。
